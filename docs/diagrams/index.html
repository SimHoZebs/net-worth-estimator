Unified Projection Architecture

Design changes: initial versus as built → 1. Architecture overview 2. Data ingestion 3. Unified data model 4. Recurrence workflow 5. Incremental slices 6. Slice lifecycle 7. Evaluation plugins 8. Unified read API

1. Architecture overview

The six blocks end to end: ingestion, unified model, shared pipeline, incremental cache control, evaluation plugins, unified read API.

2. Data ingestion

Providers supply transactions through the ingest orchestrator plus adapters. Manual entry writes directly.

3. Unified data model

Accounts, transactions, recurrence rules, checkpoints, and Monte Carlo statistics. Source decides fact versus output.

4. Recurrence workflow

Rules classify as deterministic or stochastic, run through the baseline engine or the Monte Carlo runner, and land in the unified reader.

5. Incremental slices

One projection state owns yearly slices. Slices generate transactions, statistics, and evaluation outputs. No generated checkpoints persist.

6. Slice lifecycle

Writes mark a single dirty date. The first invalid slice starts the suffix rebuild; the prefix is adopted and the revision publishes.

7. Evaluation plugins

The reader answers from stored rows. The simulator runs branch evaluations, including isolated what-if inputs.

8. Unified read API

Canonical requests assemble from slices. Anything else computes directly through the existing kernels.
