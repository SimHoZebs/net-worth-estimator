# Backend Assumptions and Contracts

This file records stable backend contracts that are easy to break while changing storage, HTTP behavior, numeric execution, or evaluation orchestration. Code references these anchors where a behavior must remain stable.

## System and Persistence

- **A1 — Authoritative runtime.** The Go server owns validation, persistence, deterministic simulation, stochastic simulation, and evaluation execution. `PRODUCT_INTENT.md` defines product intent independently and does not define wire or storage details.
- **A2 — Durable artifact behavior.** Completed deterministic results and completed seeded stochastic results may be stored in `projection_artifacts`. Identity is a versioned SHA-256 content key over the resolved model, request overrides, effective projection settings, enabled evaluation configs, income snapshot, and, for stochastic work, requested run count and seed. A completed seeded result is durable with the SQLite file; a partial result never becomes durable. Unseeded stochastic work is neither cached nor shared. Reads and writes are best-effort: a lookup/write failure must not suppress the requested computation. The table is bounded to 256 rows across deterministic and stochastic kinds.
- **A3 — Store boundary.** Callers depend on `store.Store`, not SQLite details. `store.Open` owns migrations and enables WAL, foreign keys, a 5-second busy timeout, and one connection. Production remains a single-writer deployment unless the persistence contract and concurrency model change together.
- **A4 — Stochastic stream contract.** The stochastic endpoint uses SSE. Event names are `progress`, `partial`, `result`, and `error`. `partial` payloads are cumulative snapshots. Seeded identical requests may attach to one in-process run; a completed seeded result is retained in SQLite. An unseeded run remains bound to its request and is canceled on disconnect.
- **A5 — Row ownership.** Checkpoints and postings use `source: "model" | "simplefin"`. Model saves ignore incoming ownership, reserve the `sfin-` posting namespace, preserve stored sync rows, and let an owner checkpoint override a sync checkpoint at the same account/date key. Sync never overwrites an owner checkpoint.

## Wire and Validation Contracts

- **A6 — Dates and bounds.** Public dates use `YYYY-MM-DD`. Month and year cadence clamps to the target month length. Account bounds use finite sentinels `types.NoFloor = -1e13` and `types.NoCeiling = 1e13`; CSV accepts `Infinity` and `-Infinity` only as import spellings for those bounds.
- **A7 — Validation authority.** `domain.ValidateFinancialModel(document, incomeData)` is the cross-field validator for model reads, saves, and simulation preparation. Error-severity issues block persistence and simulation; warnings do not. The deterministic endpoint returns preparation issues in an HTTP 200 body, while the stochastic endpoint reports preparation failure through an SSE `error` event after the stream has started.
- **A8 — Request-scoped overrides.** `types.ModelOverrides` can add accounts and postings or disable existing IDs for one request. `types.ApplyModelOverrides` returns a new effective document. Overrides are never stored.
- **A9 — JSON identity.** Dates remain strings, `ProjectionPath.projectionStartPostingState` is a plain JSON object, and evaluation `deterministic` and `probabilistic` values remain arbitrary JSON. The model and income payloads resolved by a projection handler are the inputs to validation, cache identity, and simulation.

## Numeric Contracts

- **A10 — Golden tolerance.** `backend/internal/domain/golden_test.go` compares numeric golden values with relative-scaled tolerance `1e-9 * max(max(abs(expected), abs(actual)), 1)`. Coverage includes deterministic projection, checkpoint replay, income resolution, and seeded stochastic bands, milestones, and evaluations. Tighten this tolerance only with matching evidence across all covered fixtures.
- **A11 — Seeded random behavior.** A non-null seed creates the established 31-bit linear-congruential sequence `(state * 1664525 + 1013904223)`, with the multiply/add performed as `float64`, followed by modulo `2^32` reduction and mask `0x7fffffff`. Do not replace it with unrestricted exact integer arithmetic. Uniform values use `state / 0x7fffffff`. Sampling consumes two uniforms per variable annual rate and uses the established log-normal transform. Samples are created sequentially and accumulated in submission order even when path simulation uses workers. A null seed uses a fresh local source and is not cache- or share-eligible.
- **A12 — Rounding.** Keep the two current rounding rules explicit. Deterministic public currency, fulfillment amounts, and evaluation summaries use `math.Round`, whose half cases round away from zero. Stochastic net-worth samples use `mathRound(value) = math.Floor(value + 0.5)`, whose half cases round toward positive infinity. Currency summaries multiply by 100, apply `math.Round`, and divide by 100. Changes to a negative half value are contract changes.

## Domain Semantics

- **A13 — Structural movement and ordering.** Source/destination presence, not IDs, labels, categories, or rates, selects external inflow, external outflow, or transfer behavior. `enabled` controls participation. Same-date occurrences execute by ascending `priority`, then declaration index. Annual caps apply per posting and calendar year.
- **A14 — Historical boundary.** Enabled one-time postings strictly before the projection start replay through shared transitions. A start-date one-time posting remains projected unless a start-date checkpoint makes that date observed. Same-date postings execute before checkpoints; checkpoints overwrite observed account balances. Historical replay carries balances, latest realized posting amounts, and annual-cap state but emits no projected movement or evaluation events.
- **A15 — Shared transitions.** Deterministic execution, sampled execution, and financial-independence branches all use `TransitionRuntime`. Behavior-generated withdrawals request `AccountMovementAction`; they do not mutate balances directly. Source-funded movement clamps to positive withdrawable balance, destination movement clamps to ceiling headroom, and every movement records requested amount, realized amount, and ordered account deltas.
- **A16 — Evaluations.** `EvaluationRegistry` owns financial independence, net-worth threshold, and posting fulfillment. `types.EvaluationTypeOrder` fixes type order, each table preserves row order, and instance IDs are unique across all evaluation tables. Financial independence uses explicit source and continuing-posting IDs. It does not infer continuing behavior from row identity, labels, categories, or rates.
- **A17 — Percentiles and stochastic completion.** `domain.StochasticProjection` returns a result only after all normalized runs complete. Percentiles are computed from complete sorted per-date values. Partial results may omit unfinished dates, but they are never persisted or treated as a final distribution.
- **A18 — SimpleFIN transaction.** Balance checkpoints and disabled pending-charge postings are applied in one transaction. Owner checkpoint collisions win. Pending rows are refreshed only for the configured card accounts and reserved prefix. Dry-run returns planned counts and rolls back all writes.
- **A19 — Access precedence.** Read-only mode rejects guarded writes with 403 before bearer validation. With writable mode and a configured token, a missing or wrong bearer is 401. Reads and projection computation remain available. Origin filtering and write authorization are separate controls.
- **A20 — Seed behavior on startup.** CSV is seed data for an empty canonical store and explicit offline import data. A populated SQLite database is authoritative across restarts. Seed-file changes do not implicitly replace canonical state.
